title: Migration notes
description: Breaking changes and how to update code written for earlier versions of SGL.
---

SGL has no releases yet, so these notes are organized by topic, not by version. Each section
describes a change and how to update existing code.

## Frame timing

`Application.frame(dt)` now receives seconds consistently on Canvas and OpenGL backends. Low-level Canvas applications that previously treated `dt` as milliseconds must convert explicitly when calling legacy millisecond-based code:

```scala
legacyUpdate((dt * 1000.0).toLong)
```

## Current conventions

- The core is shared by all games. Engines are optional architectures on top of it.
- Vectors, matrices, shapes, and collisions live in `sgl.geometry`.
- GameObject engine packages use `sgl.engine.gameobject`.
- GameObject 2D rendering is OpenGL-backed.
- Static files should be declared with typed asset rules and consumed by `sgl_core_library`.

## sgl.math is now sgl.geometry

`sgl.math` hid `scala.math` in files that import `sgl._`, so `math.sin` did not compile. Replace
`sgl.math` with `sgl.geometry` in imports, and `math.Vec2` and similar names with `geometry.Vec2`.
`import scala.math` next to `import sgl._` is no longer needed.

`sgl.util.Math` was removed for the same reason: use `degrees.toRadians` and `radians.toDegrees`, which
are part of Scala. `sgl.util.MathUtils` has `clamp`, `lerp`, and similar helpers.

## Saves on the desktop are explicit

`sgl_desktop_awt_app` and `sgl_desktop_lwjgl_app` kept saves in memory when `file_save` was not
set, which lost them when the game stopped. A game that needs a `SaveComponent` now has to say
how it saves, or it does not compile:

```python
file_save = "mygame.save"                  # in a file
save_component = "MemorySaveComponent"     # or, as before, until the game stops
```

`FileSave` now throws an `IOException` when it cannot read or write its file. It used to report no
save, and to lose what was written. Existing files still read.

## Scrolling

`mouseScrolled(amount: Int)` is now `mouseScrolled(amountX: Float, amountY: Float, unit)`, and comes
from every desktop backend too. What was `amount`, in browsers, is `amountY` in `Pixels`.

## Resource paths to typed assets

Old application code often loaded resources by path:

```scala
Graphics.loadImage(ResourcesRoot / "drawable" / "player.png")
Audio.loadMusic(ResourcesRoot / "audio" / "theme.wav")
System.loadText(ResourcesRoot / "levels" / "level1.tmj")
```

New application code should use generated typed assets:

```scala
Graphics.loadImage(Assets.drawable.player)
Audio.loadMusic(Assets.audio.theme)
System.loadText(Assets.text.level1)
```

Declare assets with rules such as `sgl_drawable_assets`, `sgl_audio_assets`, and `sgl_text_assets`, pass those targets to `sgl_core_library(assets = [...])`, then add the generated provider mixin to each backend app:

```python
extra_mixins = ["my.game.core.GeneratedAssetsProvider"]
```

`ResourcesRoot`, backend serving roots, and packaged resource names are framework/backend details. They should not be used as the public asset API in game code.

## Asset rule names

The old generic `sgl_resource_assets` rule has been removed. Use typed rules instead:

- images for rendering: `sgl_drawable_assets`
- exact image files: `sgl_raw_image_assets`
- text: `sgl_text_assets`
- binary: `sgl_binary_assets` (`BinaryAsset` is distinct from `RawImageAsset`)
- audio: `sgl_audio_assets`
- fonts: `sgl_font_assets`

`name_strip_prefix` was also removed. Use the single `strip_prefix` attr to derive typed names from source paths.

## Tiled maps

Prefer real Tiled project/layout files plus `sgl_tiled_import` instead of checked-in rewritten map JSON. The import rule rewrites Tiled image references to typed drawable asset URIs and emits assets for `sgl_core_library`.

## GameObject engine

The engine core no longer knows about spatial objects. `Spatial2D` and `Spatial3D` are ordinary
components, and their creation helpers are extensions in the `spatial2d` and `spatial3d`
packages:

```scala
context.spawn2D("Player", Transform2D(position = spawn))
  .attach(new PlayerController(_))

gameObject.component[Spatial2D].foreach { spatial =>
  spatial.local = spatial.local.copy(position = nextPosition)
}
```

- The convenience accessors `gameObject.spatial2D`, `world.spatial2D`, and `world.objectWith` were
  removed. Use `component[Spatial2D]`, `world.index[A]`, or `world.single[A]`.
- `Spatial2DModule`, `Spatial3DModule`, and their systems were removed. Global transforms are
  computed from the parent chain when read, so remove the `.install(Spatial2DModule)` calls.
- `Updatable` and `FixedUpdatable` components require `UpdateCapabilitiesModule`. Attaching one
  without the module throws a `CompositionError`.
- `World` creation methods take a `using Scope` with no default. Add `(using Scope)` to helpers
  called from scenes, or `import world.given` for the global scope. Objects created through
  `GameContext` helpers go into the current scene's scope.
- The block builders (`context.gameObject2D(name) { obj => ... }` and the 3D variant) were removed.
  `child2DOf` and `child3DOf` became `childOf` in a chain: `spawn2D(name).childOf(parent)`.
- Objects are now `TypedObject`s. Compose them as a chain of `attach`, and have components that
  depend on other components take a `TypedObject[...]` constructor parameter instead of looking
  them up with `require`. See
  [composition checked by the compiler](/docs/gameobject/#composition-checked-by-the-compiler).
- `GameObject2D` and `GameObject3D` are now aliases of `TypedObject[Spatial2D]` and
  `TypedObject[Spatial3D]`. The wrapper classes, `attach2D`, `attach3D`, and `.typed` were
  removed: call `attach` directly on the result of `spawn2D` or `spawn3D`.
- Engine components take a typed object instead of an owner. `SpriteRenderer` and `Tilemap` need a
  `GameObject2D`, `MeshRenderer` needs a `GameObject3D`, and the cameras and overlays take a
  `TypedObject[Any]`. Their runtime `requires[Spatial2D]` is now a compile-time check.
- Components that still take a plain `owner: GameObject` are attached to typed objects with
  `attachPlain`. `context.spawn(name)` creates an object without a spatial.
- `ComponentKey` and the `given` each component declared in its companion were removed, along with
  `.requires[B]` and `.requiresContext[B]`. Components are stored and indexed by their concrete
  class. A requirement on the world is declared on a trait with `RequiresGlobals`.
- `ContextKey` was removed and the world's context is now its globals: `world.context` became
  `world.globals`, `builder.setContext` became `builder.setGlobal`, and
  `context.world.context.get[A]` is `context.global[A]`. Values are stored under the class they
  are set as, so delete the `given ContextKey` declarations.
- `createObject2D` and `createObject3D` were renamed `spawn2D` and `spawn3D`. `world.createObject`
  still creates a plain `GameObject`.
- A component built from a typed object extends `ComponentOf(obj)` instead of declaring
  `override val owner`.
- Drawing is now done by modules. Install `Render2DModule` for sprites, tilemaps, text overlays
  and circle masks, and `Render3DModule` for meshes and `Camera3D`; without the module, attaching
  one of those components throws a `CompositionError`. `Renderer.render(world)` was replaced by
  `beginFrame` and `endFrame` around a new `Render` stage.
- `TextOverlay` and `CircleMaskTransition` moved from `render2d` to the `extras` package, and each
  has its own module: install `TextOverlayModule` or `CircleMaskModule`. `TextOverlay` gained an
  `order` among screen drawings.
- Games can draw their own components: a system in the `Render` stage submits to
  `context.global[Render2D]`. See
  [drawing your own components](/docs/gameobject/#drawing-your-own-components).
- Meshes, textures, and materials are released with the scope they are created in: drop the
  release calls from `Scene.unload`. Their creation methods take a `using Scope`, which a scene
  has. `AssetId[...]` and the `Asset` traits are replaced by plain `Mesh` and `Material` handles,
  `renderer.loadTexture2D` returns a `Texture2D`, and `Engine` and `Renderer` have no type members.
- `Camera3DView` was removed. `Camera3D` now takes a `GameObject3D` and is placed by its
  transform: instead of writing a view matrix, set the camera object's `spatial.local`, for example
  with `Transform3D.lookAt(eye, target, up)`, or parent the camera to another object.
- `world.single[A]` and `world.requireSingle[A]` throw when the world holds more than one `A`
  instead of returning the first.
- `attach` is no longer available through `HasGameObject`: call it on a `TypedObject` or a
  `GameObject`, not on a component or domain object.
- Destroying an object now destroys its children in the hierarchy; they used to become roots.
  `destroySubtree()` was removed: call `destroy()`. Call `clearParent()` first on a child that
  must survive.
- The engine's `System` was renamed `GameSystem`, so it no longer shadows `java.lang.System` or
  the `System` of `SystemProvider`. A `GameSystem("id") { ... }` block is given a `Scope` as well as the `GameContext`.
- `FixedDeltaTime` gained `maxStepsPerFrame` (default 8): a frame no longer runs an unbounded
  number of fixed steps.
- The application's `pause` and `resume` run the new `Pause` and `Resume` stages.
- `context.dt` replaces `context.global[DeltaTime].seconds.toFloat`, and `world.find(id)` looks an
  object up by its `ObjectId`.
- `GameRuntime` is built with `GameBuilder.build`; its constructor is no longer public.
- The `typed`, `hierarchy`, `schedule`, `capability`, and `runtime` packages were merged into
  `sgl.engine.gameobject`: replace those imports with `import sgl.engine.gameobject._`. The
  `spatial2d`, `spatial3d`, `render2d`, `render3d`, and `extras` packages are unchanged.
- Colors are a `Color(red, green, blue, alpha = 1f)` instead of a tuple of four floats: write
  `SpriteVisual.Triangle(Color(1f, 1f, 1f))`. `ClearColor` is unchanged.
- A frame's delta time is capped by the new `MaxDeltaTime` global (0.25 s by default).
- `context.setGlobal(value)` sets a global for the lifetime of the current scope, and `Scene` gained
  `pause` and `resume`.
- Scenes can load before they appear: see [`AsyncScene`](/docs/gameobject/#scenes-that-load-first).
  Code that created objects from a `Loader` callback should use `context.whenLoaded(loader) { ... }`
  instead, which runs on the game thread and is dropped when the scene is left.
- `GameContext.scope` was removed. `context.spawn2D`, `spawn3D`, `spawn`, and `createObject` create
  in the given `Scope`, so a helper that takes a `GameContext` and creates objects needs a
  `(using Scope)`.
- `engine.loadDrawableTexture` and `loadRawImageTexture` were removed. Use
  `renderer.loadTexture2D(asset)`, which needs a `Scope`, and `renderer.whenReady(texture)` for the
  `Loader`. These textures used to stay loaded for the whole game and are now released with their
  scope: load the ones to keep in the world's global scope.
- Materials accept textures from an atlas. `renderer.loadTexture2D` of a packed drawable now draws
  from its page.
- `GameModule.install` takes a `GameSetup` instead of a `GameBuilder`, so that a module can also be
  installed in a scene: change the parameter type. Installing a module twice in the game now has no
  effect the second time. `SceneLoading` is no longer a case class.
- `Renderer.drawMeshes` was replaced by submitting meshes to `Render3D`. An implementation of the
  core `OpenGL` trait needs the new `depthMask`, `textureUnit`, `maxTextureUnits`, `One`, and
  `blendFuncSeparate`.

## Web builds

- `<name>_site` (from `sgl_html5_app` and `sgl_html5_opengl_app`) is the deployable website.
  Replace scripts that copied `<name>_indexjs` and the assets into a site layout by hand with
  it, and a custom page with `html_template` plus `site_files`.
- In that site and in the dev server, the JavaScript module sits at the root (`index.js`),
  not under the package path.
- `sgl_html5_opengl_app` lays out its canvas like the Canvas rule: by default it is centered on
  a dark page. Set `center_canvas = False` to keep the previous behavior, where the canvas stays
  where the page puts it. `Html5OpenGLApp.canvasDimension` is replaced by `theme`.
- The fixed-size theme centers against the viewport instead of the body's content height, so a
  canvas on an otherwise empty page is now centered vertically too.
