Every backend implements the core providers for one platform. The game core is the same for all
of them. Each backend has a Bazel rule that generates the entry point, as described in
[Bazel rules](/docs/bazel-rules/).

| Backend | Rule | Rendering | Audio | Saves (default) |
| --- | --- | --- | --- | --- |
| Desktop AWT | `sgl_desktop_awt_app` | Canvas (Java2D) | JavaSound | File (`file_save`) or memory |
| Desktop LWJGL | `sgl_desktop_lwjgl_app` | OpenGL 3.3 core, plus Canvas through `OpenGLCanvasProvider` | OpenAL | File (`file_save`) or memory |
| Desktop Metal | `sgl_desktop_metal_app` | Metal, plus Canvas and the bundled OpenGL subset | AVFoundation | Not included |
| HTML5 Canvas | `sgl_html5_app` | Canvas 2D context | HTML5 audio | `localStorage` |
| HTML5 WebGL | `sgl_html5_opengl_app` | WebGL 2, plus Canvas through `OpenGLCanvasProvider` | HTML5 audio | Not included |
| Scala Native | `sgl_desktop_native_app` | SDL2 with OpenGL ES 3. `NativeApp` for Canvas, `NativeOpenGLApp` for OpenGL. | SDL2 audio | Not included |
| Android | `sgl_android_app` | Android Canvas through the proxy platform | Android | SharedPreferences |
| Headless | `//backends/headless-opengl` | OpenGL through Mesa EGL, without a display | Silent (`FakeAudioProvider`) | Not included |

```bash
bazel run //examples/hello-canvas:desktop-awt
bazel run //examples/hello-canvas:desktop-metal
bazel run //examples/hello-scalagl:desktop-lwjgl
bazel run //examples/hello-scalagl:html5            # http://localhost:8080
bazel run //engines/gameobject/examples/asteroids:desktop-native
bazel run //examples/snake:android-run              # installs and launches on a device
```

## Desktop JVM

Use **AWT** for Canvas games during development. It has no native dependencies, and Bazel runs it
on a downloaded JDK 17. Use **LWJGL** for OpenGL games and the GameObject engine. Both can simulate
a mobile safe area: set `simulated_safe_area_insets` on `sgl_desktop_awt_app`.

## Apple Metal

The macOS Scala Native backend runs the batched Canvas renderer through fixed Metal pipelines. It supports solid geometry, transforms, clipping, bitmap textures, alpha blending, the portable glyph atlas, framebuffer capture, AVFoundation audio, input events, and the OpenGL subset used by the bundled ScalaGL and GameObject examples.

```bash
bazel run //examples/snake:desktop-metal
bazel run //examples/hello-canvas:desktop-metal
```

Metal targets compile an Objective-C bridge and link AppKit, Metal, and QuartzCore. They require macOS and are tagged `manual`, so wildcard builds on other platforms do not select them. The bundled Snake, Hello Canvas, Hello ScalaGL, Hello Atlas, Screen2D Board, Menu and Platformer, and GameObject Asteroids and Solar System examples have Metal targets.

### Experimental iOS foundation

Scala Native can emit arm64 static archives for iOS devices and the iOS Simulator. A Swift-owned UIKit/`MTKView` shell supplies the drawable and forwards resize, safe-area, lifecycle, stable touch identifiers, and audio-session changes through a narrow C ABI. Snake runs through the shared Canvas Metal renderer in the iOS Simulator; packaging the remaining examples is ongoing work.

```bash
bazel build //examples/ios-static-library:snake_ios_simulator
bazel build //examples/ios-static-library:snake_ios_device
bazel test //examples/ios-static-library:snake_swift_link_smoke_test
bazel test //examples/ios-static-library:ios_snake_runtime_test
examples/ios-static-library/build_simulator_app.sh /tmp/SGLIOSSnake.app
```

## Web

`sgl_html5_app` and `sgl_html5_opengl_app` compile the core with Scala.js. `bazel run` serves the
game on port 8080, or on the port in `PORT`. To deploy, build `<name>_site`: it is the same
directory the server uses, so copy it as it is to any static host.

```bash
bazel build //:html5_site
cp -rL bazel-bin/html5_site _site   # e.g. for actions/upload-pages-artifact
```

Useful options:

- `html_template` replaces the generated page with your own, and `site_files` adds the files it
  refers to, such as an icon. The page imports `{{JS_PATH}}` and calls
  `{{MAIN_CLASS}}.run(canvas)`.
- By default the canvas has a fixed size and is centered on a dark page. `center_canvas = False`
  keeps the size but leaves the layout to your page, so the canvas can sit inside any element.
  `fullscreen = True` fills the page, and `use_provided_canvas = True` takes the size your CSS
  gives the canvas.
- `keyboard_capture = "canvas_focused"` only captures keys while the canvas has focus, so the game
  can be embedded in a page with other inputs.
- `pack_assets = True` bundles every asset into one binary pack.

<Aside type="note" title="iOS packaging">
The native Metal shell is experimental. A web build can still be packaged as an iOS app with
[Cordova](https://cordova.apache.org/). `backends/html5/cordova` has the integration, and
[Fish Escape](https://apps.apple.com/us/app/fish-escape-lite/id1515164224) shipped this way.
</Aside>

## Scala Native

`sgl_desktop_native_app` produces a native executable that runs without a JVM. It needs SDL2,
SDL2_image, and OpenGL ES libraries. OpenGL apps set `backend_app = "NativeOpenGLApp"` and
link `-lGLESv2`. The Canvas backend draws with the same OpenGL Canvas renderer as LWJGL and WebGL.

## Android

The Android backend is a Kotlin library in `backends/android-kotlin`. `sgl_android_app` generates
a Gradle project that wraps your core. See [Android](/docs/android/) for wiring, build
requirements, system bars, and Play services.

## Asset roots

Game code uses [typed assets](/docs/assets/) and never refers to where a backend stores files:

- JVM desktop loads classpath resources packaged in the core library.
- HTML5 serves copied assets under the generated `Html5AssetsServingRoot`.
- Scala Native loads copied assets under `NativeAssetsRoot`.
- Android maps resource names to `res/drawable-*` and `assets/`.

This is why HTML5 and Scala Native rules take `assets` and `assets_strip_prefix`: they copy the
files next to the generated app.
