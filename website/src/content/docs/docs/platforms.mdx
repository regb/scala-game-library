Supported backend families include:

- Desktop JVM with AWT Canvas
- Desktop JVM with LWJGL/OpenGL/OpenAL
- HTML5 Canvas and WebGL via Scala.js
- Desktop native via Scala Native and SDL2
- Android through the proxy backend / Android Kotlin integration

```bash
bazel build //examples/hello-canvas:desktop-awt
bazel build //examples/hello-scalagl:html5
bazel build //engines/gameobject/examples/asteroids:desktop-native
```

## Android wiring

Android uses the core proxy providers. Define a wiring entry point in shared Scala code so provider-backed fields are initialized only after the platform proxy:

```scala
object Wiring {
  def wire(platform: PlatformProxy): ProxiedGameApp =
    new WiredProxyPlatform(platform) with AbstractApp
}
```

Games that persist state can also mix in `ProxySaveProvider` and define a stable `SaveName`. Point `sgl_android_app.wiring_expression` at `Wiring.wire(platformProxy)` when the Android package differs from the core package. Running an Android target, rather than merely building it, generates the Gradle project and assembles the APK:

```bash
bazel run //examples/snake:android-debug
```

### Android system bars

Android apps use immersive fullscreen by default. The navigation and status bars stay hidden while the game uses the full display, and an edge swipe reveals them temporarily.

Configure this with `sgl_android_app`:

```starlark
sgl_android_app(
    name = "android",
    # "immersive", "safe-area", or "edge-to-edge"
    system_bars_mode = "immersive",
    # "transient-by-swipe" or "default"
    system_bars_behavior = "transient-by-swipe",
    navigation_bar_contrast_enforced = False,
    # ...
)
```

Android support starts at API 26, Android 8. Generated apps target API 37. On Android 15 and later, apps targeting API 35 or later use platform-enforced edge-to-edge without deprecated window setup calls. Earlier devices, and custom apps targeting older APIs, use a version-gated compatibility implementation. Do not opt out of edge-to-edge enforcement in a custom theme.

`safe-area` leaves the bars visible and keeps the whole game surface outside system bars, display cutouts, and gesture regions. Its `Window.safeArea` is zero because the surface is already inset. `edge-to-edge` leaves the bars visible and lets the surface draw beneath them. `immersive` hides the bars and also uses the full surface. In both full-surface modes, use `Window.safeArea` to protect controls while drawing backgrounds across the window. Insets reserve bar space even while bars are hidden, so transient bars do not move controls. Games can paint unsafe areas themselves, including a black bottom area.

Android 11 and later allow rendering into cutouts on every edge. Android 9 and 10 allow short-edge cutouts but may letterbox long-edge cutouts. `navigation_bar_contrast_enforced` controls Android's automatic navigation-bar scrim on Android 10 and later.

Play's general edge-to-edge compatibility recommendation is separate from its deprecated-API warning. Deprecated calls remain in compatibility code and may also exist in dependencies, so Play may still flag the packaged app even though those calls are not used by the modern path. Neither warning is guaranteed to clear until Play analyzes a newly uploaded release.

## OpenGL-backed Canvas

`OpenGLCanvasProvider` implements the Canvas API on top of the portable `OpenGLProvider`. It renders solid shapes, transformed and clipped geometry, bitmap regions, alpha blending, lines, ovals, and text with shaders and triangle batches. The same implementation compiles for desktop OpenGL, WebGL 2, and Scala Native OpenGL ES.

Mix it into any OpenGL runner after the game application trait:

```scala
object Main extends LwjglApp
  with MyCanvasGame
  with OpenGLCanvasProvider
  // platform providers
```

Default Canvas text uses a bundled Noto Sans glyph atlas and shared metrics. AWT and OpenGL Canvas therefore use the same glyph advances, baselines, wrapping, alignment, and text-box sizing. Regular and bold faces are included. The OpenGL renderer currently falls back to Noto Sans when asked to load another font asset.

The Scala Native Canvas runner now uses this renderer instead of its former fixed-function OpenGL implementation. The Hello Canvas example provides OpenGL-backed targets for JVM and WebGL:

```bash
bazel run //examples/hello-canvas:desktop-lwjgl
bazel run //examples/hello-canvas:html5-opengl
```

## Frame capture

Every application backend implements `FrameCaptureProvider`. A request completes after the next frame that starts after the request, and returns top-left, tightly packed RGBA8 pixels:

```scala
captureNextFrame().foreach { frame =>
  println(s"captured ${frame.width}x${frame.height}")
}
```

The core API returns pixels rather than choosing a file format or storage mechanism. Desktop JVM applications can encode the result with `DesktopFrameIO.writePng(frame, path)`.

The desktop AWT and LWJGL examples include an opt-in screenshot mixin. This captures after 30 warm-up frames:

```bash
SGL_SCREENSHOT_PATH=/tmp/frame.png bazel run //examples/hello-canvas:desktop-awt
SGL_SCREENSHOT_PATH=/tmp/frame.png bazel run //examples/hello-scalagl:desktop-lwjgl
```

Set `SGL_SCREENSHOT_DELAY_FRAMES` to change the warm-up period.

### Headless OpenGL

The `//backends/headless-opengl:sgl-headless-opengl` backend creates a Mesa surfaceless EGL pbuffer. It needs no X11, Wayland, or physical GPU. Mix `HeadlessOpenGLApp` into an application, then drive the game and its input explicitly:

```scala
app.start()
try {
  app.Controller.keyDown(Input.Keys.Right)
  app.step(1.0 / 60.0)
  app.Controller.keyUp(Input.Keys.Right)
  app.step(1.0 / 60.0)
} finally app.stop()
```

`Controller` accepts keyboard, mouse, touch, scrolling, and system-action events from any thread. `step` dispatches queued events on the OpenGL thread before updating the game. A controller can request frames with `captureNextFrame` when it needs an observation.

On Linux, set `EGL_PLATFORM=surfaceless` and `LIBGL_ALWAYS_SOFTWARE=1` to force Mesa software rendering. The backend's Bazel test also clears `DISPLAY` and `WAYLAND_DISPLAY` and checks that OpenGL reports llvmpipe.

## Asset roots

Application code should use typed generated assets. Backend-specific roots are implementation details:

- JVM desktop loads packaged classpath resources from the core target.
- HTML5 serves copied assets below the generated `Html5AssetsServingRoot`.
- Scala Native loads copied assets below `NativeAssetsRoot`.
- Proxy backends, including Android Kotlin, receive plain string resource names from SGL and map them to platform-specific asset systems.

Bazel app rules generate the backend-specific root overrides; game code should not depend on those root strings.
