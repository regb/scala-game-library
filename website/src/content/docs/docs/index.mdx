The Scala Game Library (SGL) is a **code-first, declaratively composed, compiler-verified**
cross-platform game framework in Scala. Everything—game logic, scenes, components, assets, and
platform targets—lives in concise, plain-text source and Bazel files, with no binary editor state
and no runtime wiring surprises.

You write one portable core against typed APIs for the application lifecycle, rendering, input,
audio, assets, and saves, then build it with a Bazel rule for each platform you want to ship on
(Desktop JVM, Web via Scala.js, Native via Scala Native, Android, and Headless OpenGL).

Because missing providers, broken asset names, and mis-ordered components fail at compile time—and
games can be stepped and frame-captured headlessly with no display—SGL provides a tight, reliable
verification loop for both human developers and [AI coding agents](/docs/ai-agents/).

<Aside type="caution" title="Pre-release">
SGL has not had a release yet and its APIs change often. Use it if you are willing to follow the
repository and adapt to breaking changes.
</Aside>

## Getting started

<Steps>

1. **[Install Bazel](/docs/installation/)** with Bazelisk, then clone the repository or add SGL to
   your own Bazel module.

2. **Run an example.** `bazel run //examples/hello-canvas:desktop-awt` opens a window, and
   `bazel run //examples/hello-canvas:html5` serves the same game on `http://localhost:8080`.
   [Examples](/docs/examples/) lists more.

3. **[Write your first game](/docs/getting-started/)**: a game core, a desktop target, and a web
   target.

4. **[Choose an engine](/docs/engines/)** when your game outgrows a single `frame` method:
   GameObject for components and OpenGL, Screen2D for Canvas screens.

</Steps>

## How SGL is organized

<CardGrid>
  <Card title="Core" icon="puzzle">
    Provider traits such as `CanvasProvider`, `OpenGLProvider`, `AudioProvider`, and
    `WindowProvider`, plus `Input`, typed assets, saves, and `sgl.geometry`. Every game uses the core.
  </Card>
  <Card title="Engines" icon="rocket">
    Optional ways to structure a game. **GameObject** uses components, systems, and scenes on
    OpenGL. **Screen2D** uses a Canvas screen stack.
  </Card>
  <Card title="Modules and extensions" icon="add-document">
    Reusable libraries: Tiled map import, scene2d UI, particles, and live configuration for
    development.
  </Card>
  <Card title="Backends" icon="laptop">
    Implementations of the providers for AWT, LWJGL, HTML5, Scala Native, Android, and headless
    OpenGL. Bazel rules generate the entry point for each one.
  </Card>
</CardGrid>
